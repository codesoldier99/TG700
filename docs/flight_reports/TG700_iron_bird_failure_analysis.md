# TG700 铁鸟台事故现场反推分析

**——查理·芒格"反向思维"视角的 TG700 故障全排查**

**文档版本：** v1.0  
**日期：** 2026-04-24  
**适用阶段：** 铁鸟台地面通电/细流测试（飞行前）  
**系统配置：** 800V 高压 VTOL，16 台弦动科技 HV Pro SiC ESC，SkySakura H743 飞控，DroneCAN 双总线

---

> **芒格原则：** 不问"怎么飞好"，先问"怎么必然炸机"。站在事故现场，反推所有通向这个结果的路径，一条不漏。

---

## 一、电源/PDU 类——"怎样让上电瞬间就炸"

### 1.1 无预充电直接接主回路 🔴

**炸机路径：** 800V 电源直接接通 → 16 个 ESC 的输入滤波电容（每个数百至数千μF）瞬间从 0V 冲到 800V → 主回路电流峰值可达数千安培 → 接头处瞬间产生金属蒸气弧光 → XT 系列接头触点烧蚀/熔融 → 如弧光持续则引燃线束 → 电池组热失控 → **锂电火灾。**

反推：**现场没有预充电电阻回路，也没有用 XT90S 接头。**

---

### 1.2 PDU 铜排螺栓未紧固 🔴

**炸机路径：** 800V/800A 级连接点松动 → 接触电阻升高（哪怕 1mΩ 就产生 640W 热量）→ 局部温升 → 绝缘层软化 → 铜排到机架短路 → 弧光 → 火灾。

反推：**现场铜排螺栓用手拧，未用扭矩扳手，未测接触电阻。**

---

### 1.3 主保险丝选型错误 🟠

**两种炸机路径：**

- **保险丝太小**：起飞油门瞬间电流冲击 → 保险丝误断 → 16 台电机同时断电 → 飞机从铁鸟台跌落
- **保险丝太大（最常见错误）**：ESC 内部短路 → 保险丝不动作 → 电缆过热燃烧 → 火灾

反推：**现场保险丝额定值凭经验随手选，既没按悬停电流×2估算，也没分路保护。**

---

### 1.4 电池 200S 组包未均衡即上测试 🔴

**炸机路径：** 200 节串联，某节落后单体电压偏低 → 大电流放电时该节过放 → 内短路 → 热失控 → 800V 锂电组燃烧 → **现场无法扑灭（CO₂ 只能隔离表面，锂电内部产氧）**。

反推：**测试前没有逐节检查电压，没有接 BMS，凭总电压判断"看起来没问题"。**

---

### 1.5 飞控供电链路断路/环流 🟠

**炸机路径：** H743 飞控最高支持 12S（50.4V）→ 800V 系统用 ESC 的 BEC（12V/1A）给飞控供电 → 多个 ESC 的 BEC 并联形成地线环流 → BEC 输出互相抑制 → 飞控电压波动复位 → 飞控中途重启 → 所有电机输出归零 → **若电机正在运转则失控旋转。**

反推：**现场 BEC 配置未验证，多个 ESC BEC 并联未做隔离。**

---

## 二、电调/通信类——"怎样让电机收到错误指令"

### 2.1 全部 16 个电调 Node ID 相同（0x20）🔴

**炸机路径：** CAN 总线上 8 个节点 ID 相同 → 数据帧冲突仲裁失败 → 电调随机接收错误指令 → 某电机在未解锁状态突然高速旋转 → **旋翼高速旋转中的人员受伤，或螺旋桨成为抛射物。**

反推：**没有逐一用上位机配置唯一 ID 并写入 Flash，以为上电会自动分配。**

---

### 2.2 CAN 总线未安装终端电阻（120Ω）🟠

**炸机路径：** CAN 总线两端无匹配电阻 → 信号反射 → 数据帧错误率高 → ArduPilot 反复重发指令 → 帧延迟超 60ms → 电调触发"通信油门丢失保护"→ 某些电机突然切断油门，另一些维持油门 → 飞机在铁鸟台上剧烈侧翻。

反推：**总线布线时只接了信号线，没有焊接终端电阻。**

---

### 2.3 CAN 总线拥塞触发油门丢失 🟠

**炸机路径：** CAN 总线拥塞（16 个 ESC 同时广播状态，每个 20ms 一包 → 总线负载率 >80%）→ 油门指令帧延迟 >60ms → 部分电调切到 failsafe → **failsafe 是切到 0 油门还是保持最后值？若随机，则各电机输出不一致，产生不可控翻转力矩。**

反推：**状态上传周期保持默认（全部开启），没有关闭不必要的状态广播。**

---

### 2.4 ESC 固件版本不一致 🟡

**炸机路径：** 批次不同的电调固件版本不同 → 对 RawCommand 的油门映射区间不一致 → 相同指令值，不同电调产生不同转速 → 推力不平衡 → 飞机偏转 → 控制失效。

反推：**16 台电调来自不同批次，没有统一升级到同一固件版本。**

---

## 三、电机/机械类——"怎样让旋转部件变成破坏源"

### 3.1 电机相序接错，旋转方向相反 🔴

**炸机路径：** 相序接错的电机转向与设计相反 → 该电机推力方向偏错 → 对应电调混控因子方向取反 → Roll/Pitch 指令部分被抵消，甚至反向 → 姿态无法控制 → 铁鸟台翻转 → **若推力超过铁鸟台固定约束，飞机飞出。**

反推：**没有在无桨状态逐一点动每台电机，用手感受气流确认转向。**

---

### 3.2 螺旋桨未锁紧或未动平衡 🔴

**炸机路径一（未锁紧）：** 高速旋转 → 螺旋桨轴向脱出 → 高速旋转的碳纤维桨叶以百米/秒速度成为抛射物 → 人员重伤。

**炸机路径二（未动平衡）：** 不平衡量在高转速下产生周期性激振 → 电机轴承快速磨损 → IMU 过载饱和 → 姿态估计漂移 → 控制发散 → 飞机共振破坏。

反推：**螺旋桨安装后没有做静/动平衡，紧固螺母没有用防松垫片。**

---

### 3.3 电机安装倾角/方向与代码不符 🟠

**炸机路径：** 代码中 Yaw 控制因子基于特定的倾斜方向计算（CW 上桨向切向倾斜，CCW 下桨反向倾斜）→ 若实物安装方向装反 → Yaw 控制因子符号错误 → 打 Yaw 舵使飞机反向旋转 → 控制器越补越乱 → 飞机旋转失控。

反推：**安装工人没有严格对照设计图纸确认每台电机的倾斜方向。**

---

### 3.4 地面测试无螺旋桨气流，ESC 过热 🟠

**炸机路径：** HV Pro 电调要求强制风冷 → 铁鸟台测试无螺旋桨（安全考虑）→ ESC 在大电流时无散热 → MOS 管温度快速上升 → 触发过热功率降额 → 各 ESC 降额时间不一致 → 推力不均 → 姿态漂移 → 控制失效。

反推：**地面测试不带桨，没有给电调配置辅助散热风扇。**

---

## 四、飞控/软件类——"怎样让飞控发出错误指令"

### 4.1 电机序号映射错误 🔴

**炸机路径：** ArduPilot SERVO 功能分配（SERVO5~SERVO20 的 function 值）与物理电调 CAN Node ID 不对应 → Roll 输入实际变成 Yaw 响应 → 任何姿态修正都加剧失控 → 飞机在铁鸟台上翻转。

反推：**没有做逐通道电机功能验证（Mission Planner 电机测试页面逐一测试）。**

---

### 4.2 Q_ENABLE=0 或 Q_FRAME_CLASS 配置错误 🟠

**炸机路径：** VTOL 参数未正确配置 → ArduPilot 不激活 VTOL 电机混控 → 起飞时固定翼模式控制面输出 → 舵面偏转但电机无推力 → 飞机无法离地或姿态失控。

---

### 4.3 PID 增益与飞机实际动力学严重不匹配 🔴

**两种炸机路径：**

- **增益过高（最常见）**：对 11m 翼展、大惯量飞机套用小四轴默认 P=0.25 → 高频振荡 → 共振频率与机身结构频率耦合 → 机臂疲劳断裂
- **增益过低**：姿态控制带宽不足 → 外界扰动（地面风）→ 飞机缓慢翻倒

反推：**直接使用 ArduPilot 默认 PID，没有根据 TG700 的质量/惯量降增益。**

---

### 4.4 ADC3 与 ESC2 接口同时接线 🔴

**炸机路径：** H743 飞控明确警告 ADC3 与 ESC2 共用引脚 → 若两者同时接线 → **MCU 损坏** → 飞控死机 → 所有输出归零 → 电机停转 → 飞机坠落。

反推：**接线人员不了解该共享限制，同时使用了两个接口。**

---

### 4.5 飞控 12V BEC 超载导致复位 🟠

**炸机路径：** H743 的 12V BEC 最大 60W（12S 时）→ GPS + 数传 + 相机 + 载荷超载 → BEC 过温降额 → 飞控输出电压跌落 → 飞控 Brown-out 复位 → 测试中断，电机输出不可预知。

反推：**没有统计所有 12V 外设功耗总和，未验证是否超过 BEC 上限。**

---

## 五、人员操作类——"怎样用人为失误终结飞机"

### 5.1 上电前站位错误，人员进入旋翼危险区 🔴

**炸机路径（人伤）：** 电调 Node ID 冲突 → 接通电源瞬间随机电机启动 → 旋转中的螺旋桨击中旁边的操作人员。

反推：**没有制定"上电隔离区"规程，操作人员习惯性站在电机附近。**

---

### 5.2 无紧急断电装置，事故扩大 🔴

**炸机路径：** 任何一个电气异常发生后 → 没有一键断电的急停开关 → 旁观者跑过去手动拔电池 → 接触 800V 高压 → **电击死亡。**

反推：**PDU 上没有安装独立的急停接触器，也没有绝缘操作手柄。**

---

### 5.3 通话协调失败，多人同时操作 🟠

**炸机路径：** A 在地面检查电机时，B 在地面站点击"解锁" → 电机突然旋转 → A 受伤。

反推：**没有明确"唯一指挥人"制度，多人都有地面站操作权限。**

---

### 5.4 "上次测试没问题"的幸存者偏差 🟠

**炸机路径：** 上一次测试时 CAN 总线侥幸运行正常（节点冲突但没碰巧发生错误帧）→ 认为系统没问题 → 本次加大油门 → 总线负载上升 → 冲突暴露 → 电调混乱 → 炸机。

反推：**跳过上电前检查清单，依赖"之前没问题"的经验判断。**

## 六、反推结论——事故原因树

```
炸机事故
├── 电气根因
│   ├── 预充电缺失（上电即爆）
│   ├── PDU 铜排/保险未按规格制作
│   └── 电池未均衡/无 BMS（热失控）
│
├── 通信根因
│   ├── 16 台电调 Node ID 全为 0x20（最高概率）
│   ├── CAN 总线无终端电阻（信号错误）
│   └── 状态广播未关闭（总线拥塞）
│
├── 机械根因
│   ├── 电机相序未逐台验证（转向错）
│   ├── 电机倾角安装方向错误（Yaw 反向）
│   └── 螺旋桨未锁紧/未平衡（抛射物）
│
├── 软件根因
│   ├── 电机序号映射错误（控制颠倒）
│   ├── PID 增益未降（振荡共振）
│   └── ADC3/ESC2 误接（飞控烧毁）
│
└── 人员根因
    ├── 无急停装置（事故扩大）
    ├── 无上电隔离区规程（人员伤亡）
    └── 幸存者偏差跳过检查（隐患积累）
```

## 八、芒格式最终结语

> **"告诉我哪里会死，我就不去那里。"**

以上每一条路径都是**独立的炸机充分条件**，其中 **ESC Node ID 冲突 + 无预充电 + 无急停** 这三项，是在当前系统状态下**概率最高、后果最严重、最容易被忽视**的组合。

在铁鸟台通电之前，将上述清单逐条打勾，一条未过则不通电。这不是谨慎，这是**让飞机能活着飞上天的唯一路径**。
